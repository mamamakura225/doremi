# どれみ — 設計書

**なぜその作りなのか**と**不採用にした案**を残す。作るものは [requirements.md](./requirements.md)。

## 構成

```
src/lib      純ロジック（音高↔座標・スナップ・音符配列・ページ・再生スケジュール・色・コントラスト・座標変換・保存・向き判定）
src/audio    Tone.js / Web Speech API の薄いラッパー
src/hooks    DOM 計測に依存する判定（鍵盤の表示可否・向き・画面高）
src/components  SVG五線譜・符頭・音部記号・ドレミラベル・お道具箱・鍵盤・本棚・回転オーバーレイ
src/App.tsx  状態と操作の結線
```

**純ロジックは React / Tone.js / SVG から切り離す**。DOM も AudioContext も要らない形にしておくと、音高マッピングやスナップの回帰を Vitest だけで押さえられる。逆に言えば、座標計算やスケジュールを React コンポーネントの中に書かないこと。

## 主要な設計判断

### ドラッグ＆ドロップ: Pointer Events 自前実装
**HTML5 Drag and Drop API は使わない。** モバイル Safari / Chrome でタッチからの `dragstart` が実質使えず、ゴーストイメージやドロップ効果の制御もブラウザ任せになる。5歳児が指1本で音符を掴んで動かす、という中核操作をブラウザの都合に預けられない。

自前実装で必ず守ること:
- `pointerdown` で `pointerId` を記録し、**単一ポインタのみ追跡**する（子どもは画面に手をつく。マルチタッチで音符が飛ぶ事故を防ぐ）
- **すでに `drag` / `del` を追跡している間は新しい `pointerdown` を受け付けない**（[#58](https://github.com/mamamakura225/doremi/issues/58)）。`pointerId` を「記録するだけ」では単一追跡にならない——2本目の指が追跡IDを上書きし、1本目のドラッグが宙に消える。鍵盤タップも同じガードで止める
- **`pointercancel` と、掴んでいる音符（`del`）の消滅の両方で掴みを解除する**。`pointerup` だけでは戻れない経路がある: システムジェスチャでブラウザがポインタを中断したとき（→ SVG ルートの `onPointerCancel`／`onPointerUp` フォールバック）、掴んでいる音符の `<g>` が別の指の操作（↩・ページ切替）で DOM から消えたとき（キャプチャが暗黙解放され `pointerup` が個別ハンドラに届かない → レンダー中に `del.id` が `notes` に無ければ捨てる）。お道具箱側の `drag` は `<g>` が消えないのでこの穴は無いが、ドラッグ中に別の指でページ切替／クリアすると切替後の盤面に置かれる（[#84](https://github.com/mamamakura225/doremi/issues/84) で `resetBoard` 経路をまとめて対処）
- `setPointerCapture` で要素外に出ても追従する
- ドラッグ対象とコンテナに `touch-action: none` / `user-select: none`（スクロールと長押し選択に取られない）

**不採用**: HTML5 DnD（上記）／ライブラリ（dnd-kit 等。要件が「1種類の要素を五線譜に落とす」だけで、依存を増やす価値がない）。

### 譜面描画: SVG 自前実装
**VexFlow は使わない。** VexFlow は「正しい楽譜を組版する」ライブラリで、拍・小節・符幹・連桁を前提に持つ。このアプリはリズムを扱わず、音符は等間隔の固定列に並ぶだけなので、その前提がまるごと余分になる。一方で必要な「音高↔Y座標を自分で決めてスナップする」制御は、ライブラリを通すと逆にやりにくい。

自前 SVG なら、線と間の座標を自分で保持し、音部記号の切り替えは**マッピング表の差し替え**で済む（ヘ音記号 [#6](https://github.com/mamamakura225/doremi/issues/6) は実際にこの形で足した）。

記号そのものの描画は、ト音は実物のSVGパス（Wikimedia Commons の CC0 素材）を使い、**ヘ音は円と1本のカーブで自前に組んだ**（`BassClef.tsx`）。ヘ音記号は形の要点が「F線から始まる渦」と「F線を挟む2つの点」しかなく、パスを持ち込むより素直だったため。Unicode の 𝄢 は端末のフォント依存で豆腐になるので使わない。

**不採用**: VexFlow / abcjs（上記）／Canvas（要素単位の当たり判定とアクセシビリティを自前で持つことになる。SVG なら要素がそのまま当たり判定）。

### 音部記号は「表の差し替え」だけで切り替える
ト音とヘ音の違いの**中核**は、音名の並びと最上線からの step の表（`pitch.ts` の `TREBLE_PITCHES` / `BASS_PITCHES`）に閉じている。描画・スナップ・再生はすべて `Pitch` を通す。座標系（`stepToY`）は共通。

ただし表を足すのは前提の半分で、`Staff` の記号描画（`TrebleClef` / `BassClef` の出し分け）・`synth` の地の音色・ボタンのラベル・試聴音は今も clef ごとの三項分岐を持つ。3モード目を足すときはこれらを `Record<Clef, …>` 化する必要がある（[#74](https://github.com/mamamakura225/doremi/issues/74)）。`CLAUDE.md` の「表を足すだけ」は守りたい鉄則（目標）で、現状はそこまで到達していない。

- ヘ音: 最上線 = A3 = `step 0`。**音域は F2〜A3 の10音**
- ド（C3）は五線の中の間にあり、ト音の C4 と違って加線が要らない。足場ガイドは「ドの高さ」を示すものとして両モードで出す

**issue の指定は F2〜G3 だったが A3 まで広げた**（[#6](https://github.com/mamamakura225/doremi/issues/6)）。G3 止まりだと ラ が ド より下にしか無く、おてほんの「ドドソソララソ」が下降形に化けて別の曲になる。A3 までにすると ト音（C4〜E5・10音）とちょうど同じ形になり、同じ旋律がそのまま1オクターブ下で成立する。

**切り替えたら盤面はリセットする。** 置いてある音符は今の音部記号で解決された `Pitch` を持っているので、表だけ差し替えると同じ位置の音符が別の音に化ける。おてほんの切替（`toggleGuide`）と同じ扱いにした。

**リセットは `pages` を空にするだけでは足りない**（[#56](https://github.com/mamamakura225/doremi/issues/56)）。ドラッグ中に2本目の指で音部を切り替えると、`Board` 内部の `drag` / `del`（掴んでいる最中の `Pitch`）は旧音部のまま残り、離した瞬間に新しい盤面へ1音流入する。そのまま保存すると読み込み時に音域外でサイレントに消える。対策は2つ入れる:
- `Board` は `clef` prop の変化を**レンダー中に検知**して `drag` / `del` を捨てる（`prevClef` state を持つ React 公式パターン）。`useEffect` だとペイント後になり旧音部のゴーストが新しい五線に1フレーム残る。`<Board key={clef}>` で丸ごと作り直す案は、`touched` 初期化で起動ヒント（👆 さわってね）が再表示され、鍵盤が出る端末では `useFitsKeyboard` が再計測されて `viewBox` が一瞬跳ねるので採らない
- `Pitch` に `readonly clef` を持たせ、`canPlace(drag.pitch.clef, clef, x, y)`（`layout.ts` の純関数）で音部一致と配置領域（[#59](https://github.com/mamamakura225/doremi/issues/59)）をまとめて確認してから置く。上のリセットがブラウザで1フレーム遅れる窓を、値オブジェクト自身が持つ音部で塞ぐ

**残件**: `clef` 以外のリセット経路（↺ クリア・おてほん切替も `resetBoard()` を呼ぶ）でも、掴み中に指2で押せば同じ1音流入は起きる。ただしその音は**現音部で解決された正しい `Pitch`** なのでデータは壊れない（保存しても読み込みで消えない）＝「余計な音符が1つ」の不快事象に留まる。汎用の resetKey で束ねる案は別issue（[#84](https://github.com/mamamakura225/doremi/issues/84)）。

**「ト音／ヘ音」とは表示しない。** 5歳児には通じない語なので、高さのイメージで **🐤 ことり／🐻 くま** と出す。ヘ音では地の音色も低くて温かい音（サイン波・ゆっくりした立ち上がり）に変え、見た目と音の両方で「低い方の世界」に入ったことが分かるようにしている。子どもが自分で選ぶ音色（べる・ぴこぴこ）は音部記号では変えない——選んだものが勝手に変わる方が混乱する。

保存した曲は**音部記号も一緒に持つ**（`SavedSong.clef`）。音名だけでは譜面の高さが決まらないため、本棚から読み込むときはその音部記号へ盤面ごと切り替える。音部記号を持たない旧データはト音（当時の唯一のモード）として読む。本棚のミニプレビュー（`previewCells`）も同じく `song.clef` で色を引く——渡し忘れるとヘ音の曲が全部グレーになる。

**`Pitch` を引く関数（`pitchByNote` / `snapYToPitch`）に clef の既定値を置かない。** ト音とヘ音の音名は完全に非重複なので、渡し忘れるとヘ音側で 100% `undefined`／端の音になり、しかも既定引数のせいで**型検査に一切引っかからない**（[#54](https://github.com/mamamakura225/doremi/issues/54) は `synth.ts` と `Bookshelf.tsx` がこれで壊れていた）。必須引数にすれば `tsc` が渡し忘れを即エラーにする。`playMelodyNote` は `synth.ts` のモジュール変数 `clefMode` を渡す。

**不採用**: `playMelodyNote(pitch: Pitch)` にして `clefMode` 依存を消す案（App 側は再生 tick で完全な `Pitch` を持っている）。発音経路（`playNote`・おてほんのキラキラ含む）の引数を一斉に変える必要があり #54 のスコープを超える。前提は「音部の切替は必ず盤面リセット＋タイマー破棄を伴う」こと——これが崩れると `clefMode` と盤面がずれて #54 と同じ壊れ方をする。二重状態の解消は音色分岐の整理（[#74](https://github.com/mamamakura225/doremi/issues/74)）に寄せる。

### 音高 ↔ Y座標のマッピング
五線の**最上線からの半スペース数**（`step`・下方向が正）を単一の座標系にする。線と間を等しく1ステップとして扱うので、`step * staffSpace / 2` だけで Y が出る。

- ト音記号は最上線 = F5 = `step 0`、C4 = `step 10`（下加線1本）。ヘ音記号は最上線 = A3 = `step 0`、F2 = `step 9`
- スナップは Y → 生 step → `Math.round` → 最近傍の演奏可能音。**音列は連続**（`buildPitches` が step を1ずつ詰めて作り、両音部とも歯抜けが無い）なので、最近傍探索が高すぎ／低すぎた分を自動的に端の音に寄せる。範囲内クランプの3行はこれと常に同じ結果で、消しても全テストが緑のまま＝デッドコードだったため削除した（[#69](https://github.com/mamamakura225/doremi/issues/69)）。半音・歯抜けの音列を将来入れるなら、そのとき「歯抜けで最近傍が選ばれる」テストと合わせてクランプを戻す
- **ただし配置していい領域そのものは X と Y の両方で切る**（`isOverPlacement(x, y)`・[#59](https://github.com/mamamakura225/doremi/issues/59)）。クランプは「五線の中での上下」の話であって、鍵盤の上・ヘッダーの上・ゴミ箱帯の上で離したときまで置く意味ではない。X だけ見ていた頃は、鍵盤の白鍵の上で離しても最低音が置かれていた。5歳児にとって「五線譜のどこか」以外で音符が生まれるのは因果が読めない
- 音名（`'C4'`）を正本にして、Tone.js への受け渡しも保存形式も同じ文字列で統一する

### 真ん中のドに足場ガイドを出す
下加線1本のド（C4）は五線の**外の空白**にあり、目印が無いと5歳児には置き場所が分からない。下加線スナップ領域に半透明の足場（赤い破線＋楕円）を常時表示して、「ここに置く」を見えるようにする。加線を音符と一緒に描くだけでは、置く前に何も見えないので解決しない。

**加線そのものは描かない。** 破線の足場ガイドが常時その高さを示しているので、加線を足すと二重になる。記譜上の正しさより「どこに置くか」の手がかりを優先する。

### 譜面の左に音名（ドレミ）を常時表示する
各音の高さに音名を薄く（`opacity 0.9`・音高色）常時出す（[#23](https://github.com/mamamakura225/doremi/issues/23)）。置く前に手がかりが無いと5歳児は固まるため。`labelSize()` は低音ほど大きく描く——オクターブ違いの同名音（下の「ド」と上の「ド」）を大きさで区別させる。

これは「文字は最小限」原則の**唯一の意図的な例外**。色（音高連動）と大きさ（音域内の位置）で情報を冗長化し、読めなくても手がかりになるようにしている。だからこのラベルを「文字だから」で削ってはいけない。

### 1ページ10音・ページ連結
上限を決めているのは画面幅ではなく**列間隔**。配置領域は 670（`PLACE_LEFT` 210〜`PLACE_RIGHT` 880）で、符頭の幅は 34。列間隔の下限を `MIN_COLUMN_PITCH = 65`（符頭幅と同じくらいの余白が隣との間に残る）と決め、そこから上限は 10 音になる（[#42](https://github.com/mamamakura225/doremi/issues/42)）。この下限は `notes.test.ts` が回帰として押さえている。

最初は 12 音（列間隔 55.8）にしたが、**横向きスマホの実測で却下**した。当時 812×375 ではヘッダーが高さの65%を占めて SVG の倍率が 0.232 まで落ち、符頭は約19 CSS px・列間隔は 21 CSS px＝符頭がほぼ接していた。10 音なら 25 CSS px で、狭いながら隣とは離れる。タブレット横（1024×768）では倍率 0.93 で 62 CSS px あり、制約になっていたのはスマホ横だけ。

その後ヘッダーを畳んで（[#52](https://github.com/mamamakura225/doremi/issues/52)・後述）倍率が 0.631 まで戻り、10 音での列間隔は **42 CSS px** になった。上限を再び上げる余地はできたが、`MIN_COLUMN_PITCH` を緩める判断が要るので別issueとする。

**音符数に応じて列間隔を可変にする案は採らない**——音符を1つ置くたびに既に置いた音符が左右に動く。おてほんモードのゴーストも同時に動くので、置く場所を狙っている最中に的が動くことになる。列は常に固定グリッド。

**スクロールで伸ばす案も採らない**——5歳児に横スクロールと譜面の左右移動を同時に理解させることになる。

代わりに `pages: PlacedNote[][]` として、満杯後「つぎのうた」で空ページを追加する。再生は全ページを連結し、**ページ境界に1ステップの小休符**を入れてフレーズの切れ目を耳で分かるようにする（[#26](https://github.com/mamamakura225/doremi/issues/26)）。空ページは再生・保存から除く。

**全消しで空になったページは、ページ移動時に畳む**（`collapseEmptyPages`・[#60](https://github.com/mamamakura225/doremi/issues/60)）。残すとページドット・`aria-label` が実際の再生内容とズレる。末尾ページは「つぎのうた」で意図的に作った空ページなので残す。畳みを**移動時に限る**のは、音符を消すたびにページ番号が動くと制作中に足元が揺れるため。表示（ドット）は次のページ移動まで古いまま——移動しない限りズレの実害が無いので許容する。

### タップ的の寸法
`preserveAspectRatio="xMidYMid meet"` なので倍率は `min(W/1100, H/viewBoxH)`。CSS px に落ちた各要素の実測:

| 端末 | 盤面(CSS) | 倍率 | 符頭 34×26 | 列間隔 67 | お道具箱 掴み半分 | 白鍵 |
|---|---|---|---|---|---|---|
| 812×375 横スマホ（ヘッダ畳み後・盤面315） | 812×315 | 0.631 | **21.5 × 16.4** | 42.3 | 75.7 × 132.5 | 鍵盤出ない |
| 1024×768 タブレット横（盤面663） | 1024×663 | 0.931 | 31.7 × 24.2 | 62.4 | 111.7 × 195.5 | 79.1 × 111.7 |

お道具箱・ページ送り・白鍵は HIG 44pt / Material 48dp を満たす。**満たさないのは「配置済み音符」だけ**で、しかも SVG のヒット判定は既定 `visiblePainted` なので実際に当たるのは 21.5 px の楕円と 4 px の符幹線だけ——5歳児の指の接触幅（25〜38 CSS px）より狭い。

対策は**配置済み音符の `<g>` 先頭に列間隔ぶんの不可視矩形**（`NOTE_HIT_W = COLUMN_PITCH` / `NOTE_HIT_H = 44`・`fill="transparent"`・お道具箱と同じ手当て）を1枚敷き、`onPointerDown` をそこで受ける（[#62](https://github.com/mamamakura225/doremi/issues/62)）。横は列間隔ぶん（42.3 CSS px・固定グリッドなので隣と重ならない）、のばす音は2列ぶん。**縦は 27.8 CSS px 止まり**——スナップ間隔 `staffSpace/2 = 25` とゴミ箱帯（[#59](https://github.com/mamamakura225/doremi/issues/59)）に挟まれ、これ以上は五線の寸法を変えないと広げられないので別issue。寸法は `notes.test.ts` が関係式で固定する。

### 音の長さは「ふつう／のばす」の2値だけ
拍・小節・音符の種類（四分／八分…）を持ち込むと、位置（音高）の学習にたどり着く前に覚えることが増える。長さは**2値だけ**にした（[#43](https://github.com/mamamakura225/doremi/issues/43)）。記譜としての正しさは追わない。

**のばす音は譜面で2列を占める。** 長さは「時間の長さ」なので、幅で表すのが5歳児にいちばん近い。列を消費しない（自分の列の中で符頭を太らせる）案も試したが、横向きスマホでは隣の符頭と接して区別がつかなくなる（列間隔の実測は上記）。列を消費する形なら、見た目の幅・占める列・鳴る長さが全部一致する。

このため**上限 `NOTE_MAX` は「音符の個数」ではなく「列数」**を意味する。`usedColumns()` が正で、`notes.length` で満杯判定をしない。

見せ方は符頭から右へ伸びる**のばしバー**（`NoteHead` の `tail`）。二分音符の白抜き符頭のような記譜上の区別は、読めない年齢には手がかりにならない。

**不採用**: 置いた音符をタップして長短をトグルする案（掴んで捨てる操作と同じ pointerdown から始まるので誤爆する。何より、5歳児は隠れたトグルを発見できない）。お道具箱に2つ並べれば「どっちを持ってくるか」で選べる。

再生は `playbackSchedule()` がステップ数の配列を受け取り、のばす音のぶんだけ次の音を後ろにずらす。発音長は `noteDuration()`——ふつうの音は従来どおり短い減衰音（`'8n'`）、のばす音は次の音の手前（`GAP_MS` 手前）まで実際に伸ばす。制作中の試聴もこの長さで鳴らす（長さは音色と違い、置く前に聞こえないと選べない）。

保存形式は音名への接尾辞（`'C4~'`）。`SavedSong` の `pages: string[][]` を保ったまま長さを載せられ、接尾辞の無い旧データはそのまま「ふつうの音」として読める。

### ドレミ色相連動
符頭を音高ごとの色で塗る。文字が読めない年齢でも「赤はド」で識別でき、譜面上の位置と色が二重の手がかりになる。虹の並びに合わせて低→高で赤→桃と変化させ、隣り合う音が似た色にならないようにしている。

**色は識別の手がかりで、視認性は輪郭で確保する。** パレット単体ではクリーム地（`#fdf6e3`）に対して 3:1 を満たさない色が多い（[#61](https://github.com/mamamakura225/doremi/issues/61)）。

| 音 | 色 | 対クリーム地 |
|---|---|---|
| ド | `#e23b3b` | 3.95 |
| レ | `#f59e0b` | 1.99 |
| ミ | `#facc15` | **1.42** |
| ファ | `#22c55e` | 2.11 |
| ソ | `#38bdf8` | 1.99 |
| ラ | `#a78bfa` | 2.52 |
| シ | `#f472b6` | 2.46 |

パレットは変えない（虹の並び・鍵盤／符頭／プレビューの色対応を壊さない）。代わりに符頭・符幹・ドレミラベル・本棚プレビューの丸に**五線と同色の輪郭**（`OUTLINE_COLOR = #5b524b`・対クリーム地 7:1）を入れ、塗り色が何であれシルエットが読めるようにする。色覚特性があっても形の視認性が色に依存しない。再生ハイライトも同色の半透明円から**塗りなしの輪郭リング**に変え、薄い符頭色でも「いまここ」が分かるようにした。`src/lib/contrast.ts` の `contrastRatio` で輪郭色 vs 地を、`NoteHead.test.tsx` で輪郭属性の有無を数値・構造で固定する。

### 鍵盤の併記は viewBox を下へ伸ばして置く
2.2:1 のビューボックスを `meet` で入れているので、**横長すぎない画面では下に使われない帯ができる**。1024×768（タブレット横）の実測では盤面の要素が 1024×636 に対して内容の高さは 466 で、**約170pxが余っていた**。鍵盤はここに置く（[#30](https://github.com/mamamakura225/doremi/issues/30)）。

具体的には、鍵盤を出すときだけ viewBox を `1100×500` から `1100×620` に伸ばす。倍率は `min(W/1100, H/620)` なので、**幅基準のままなら五線譜は1ミリも縮まない**（1024×768 実測: 鍵盤あり・なしとも倍率 0.931）。

**表示条件は要素の 高さ÷幅 が `620/1100` 以上**（`KEYBOARD_MIN_RATIO`）。これを割ると高さ基準に変わり、鍵盤ぶん五線譜が縮む。812×375（スマホ横）は 0.14 でここに該当するため出さない——横に余白はあっても縦は最初から足りていない。

**ResizeObserver は使わない。** SVGルート要素に対してコールバックが一度も飛ばないブラウザがあり（実測で踏んだ）、鍵盤が出ないまま静かに壊れる。盤面の大きさが変わるのは画面サイズ・向きが変わったときだけなので `resize` / `orientationchange` で足りる。

**ゴミ箱帯の下端を `VIEW_H` で切った**（`isOverTrash`）。切らないと、音符を掴んで鍵盤の上で離したときに捨てられてしまう。

**帯の上端（`TRASH_TOP`）は「最も低い音の符頭の下端」から `TRASH_GAP`（符頭の張り出し1つぶん ≈13.5）以上離す**（[#59](https://github.com/mamamakura225/doremi/issues/59)）。中心座標だけで決めると、ト音の C4（符頭中心 y390・回転した楕円の下端 ≈ y403.5）とゴミ箱帯の隙間が 4 CSS px しか残らず、いちばん使うドを下寄りに掴むだけで削除が成立していた。符頭の寸法（`NOTE_HEAD_RX/RY/W`・回転角・回転後の張り出し `NOTE_HEAD_RY_ROTATED`）は `layout.ts` に集約し（[#75](https://github.com/mamamakura225/doremi/issues/75) 項目1）、`notes.test.ts` が `TRASH_TOP − 符頭下端 ≥ TRASH_GAP` を両音部で押さえる。

配置できない場所（帯・鍵盤・ヘッダーの上）で指が居るときは、ドラッグ中のゴーストを指の位置に薄く（`opacity 0.35`）追従させる。行ハイライトも消える。「音符が見えているのに離すと何も起きない」を避けるため——#59 の動機（因果が読めない）を出口側にも作らない。

白鍵はその音部記号で置ける10音そのもので、符頭と同じ `SOLFA_COLOR` で塗る（譜面の音と鍵が色で結びつく）。黒鍵は本物の並びに見せるための飾りで、当たり判定を持たない（`hasSharpAbove()` が「ミ→ファ」「シ→ド」だけ黒鍵無しと判定する）。**鍵盤から音符を置けるようにはしない**——置く操作をお道具箱の1通りに保つ。

## オーディオ

### iOS の AudioContext unlock
`Tone.start()` を**ユーザー操作の中で**呼ぶまで一切音が出ない。初回タップで必ず呼ぶ。

初回タップまで無音なのを子どもが「壊れている」と受け取らないよう、**未操作時のみ起動ヒント**（お道具箱の符頭を脈動＋指アイコン＋「さわってね」）を出す（[#24](https://github.com/mamamakura225/doremi/issues/24)）。このヒントを消すタップがそのまま AudioContext の解錠を兼ねる。

Web Speech の解錠はさらに厳しく、**初回 `speak()` をユーザー操作と同じ tick で**呼ぶ必要がある。`await` を挟んだ後の `speak` では解錠されず以後ずっと無言になるため、うたモードを選んだタップハンドラから同期的に `primeSpeech()`（音量0の空発話）を呼ぶ。

### スクラブ発音は「ゾーンを跨いだ瞬間だけ」
ドラッグ中の上下移動でピクセル単位に鳴らすと、音が連打されて何の音か分からない。**音域ゾーンを跨いだ瞬間のみ**再トリガする。同一音の中では鳴らさない。

### 地の音色は音部記号で変える
ヘ音では制作中の音も再生の「ぴあの」も、サイン波＋ゆっくりした立ち上がりの丸い低音にする（クマ・ゾウの手触り）。三角波のままだと、低い音域では倍音が耳につくうえ、見た目が変わっただけで音の世界が変わった感じが出ない。

### 制作中の音は固定、音色切替は再生時だけ
音色（べる・ぴこぴこ）を制作中にも適用すると、音高の手がかりが音色の派手さに埋もれる。**配置・スクラブ中は通常のピアノ音で固定**し、音色は再生モードにだけ効かせる。

**制作中の音（`playNote`）と再生の音（`playMelodyNote`）は別系統**。前者は `makingSynths[clef]`、後者は選択中の再生音色（`getVoice(playbackVoice)`）。混同すると「地の音色を試聴するはずが選んだ再生音色で鳴る」等が起きる（[#60](https://github.com/mamamakura225/doremi/issues/60)）。**音部切替の試聴は制作側（`playNote`）で鳴らす**——切り替えたのは地の音色であって再生音色ではない。再生音色ボタンの試聴だけ `playMelodyNote`。

### うたモードは楽器音に重ねる
音名の読み上げには**音の高さが無い**。読み上げだけにすると、このアプリの目的（音高と位置の対応づけ）が壊れる。ピアノ音を鳴らした上に読み上げを重ねる。

読み上げは前の発話が残ると600ms間隔にどんどん遅れるので、`speak` の前に必ず `cancel()` してキューに積まない。端末に ja-JP 音声が無い／機内モードでネットワーク音声が使えない場合は**黙って諦める**（＝ぴあの相当に劣化するだけで無音にはならない）。録音サンプル同梱（`Tone.Sampler`）に差し替える余地は残っている。

キラキラ音（おてほん一致）は別系統の `PolySynth` に分ける。メロディ用 synth を共有すると再生中の音を切ってしまう。

### 再生の中断はタイマー削除だけでは表現できない
`playSequence` は `clearTimers()`（既に積んだ `setTimeout` を消す）と `await ensureAudio()`（初回だけ `Tone.start()` を待つ）の間に隙間がある。この隙間に ↺ クリア・音部切替・曲選択が入っても、**まだ push されていないタイマーは消せない**——await が解決したあと古いスケジュールがまるごと積まれ、存在しないページの tick が盤面を壊して白画面になる（[#55](https://github.com/mamamakura225/doremi/issues/55)）。

対策は**世代トークン**（`gen` ref）。`clearTimers()` で繰り上げ、`playSequence` は clearTimers 直後の世代を控えて `await` 後に一致を確認し、ずれていたら何も積まずに戻る。`clearTimers()` は空スケジュールでの early return より前に呼ぶ（中断は常に成立させる）。再生を状態機械にする構造的な直しは [#73](https://github.com/mamamakura225/doremi/issues/73)。

中断時（`stopMelody`）は読み上げの停止だけでなく、**鳴っている音色を `triggerRelease` する**。のばす音（[#43](https://github.com/mamamakura225/doremi/issues/43)）以降 `playMelodyNote` に秒数が渡るので「楽器音は 8n で自然減衰するから触らない」という前提は失効している（べるなら decay+release で 2秒以上残る・[#60](https://github.com/mamamakura225/doremi/issues/60)）。

再生・お祝い・保存トーストのタイマーを1つの `timers` 配列に混ぜると、`clearTimers()` が全部消すので「✓ ほぞんした」の解除タイマーまで巻き込まれてラベルが固着する。**保存トーストは専用の ref に持ち、`clearTimers` の管理外に置く**（[#60](https://github.com/mamamakura225/doremi/issues/60)）。

窓の中で ↩・💾・📚 は今も通る（クラッシュはしないが、消したはずの音が鳴る等の stale 再生は起きうる）。塞ぐには初回解錠中だけ立つ `preparing` state が要るので #73 に回し、ここでは**古い継続を世代で捨てる**方式に留める。

保険として `pages[currentPage] ?? []`（配列外アクセスの `undefined` を吸う）と、`main.tsx` の `ErrorBoundary`（render 中の例外だけ拾う。子ども向けなので「もういちど」＝リロード1つだけ）も置く。`setTimeout` コールバック内の例外はここでは拾えない（白画面にはならないが無反応になる）。配列外アクセスを型で見せる `noUncheckedIndexedAccess` は[品質ゲート](#品質ゲート)の節のとおり別issueで段階導入する。

↺ クリアは再生中も押せる唯一のボタン——await 窓の中の割り込みと、曲を最後まで聞かずに止める非常停止を兼ねる。他ボタン（再生中は全 disabled）との非対称は意図的。

## PWA アイコン
ホーム画面追加が**価値の中心**（`display: fullscreen` / `orientation: landscape` で起動される前提）なのに、当初 manifest にアイコンが1つも無く Android Chrome のインストール要件を満たしていなかった（[#67](https://github.com/mamamakura225/doremi/issues/67)）。

- **`pwa-192x192.png` / `pwa-512x512.png`**（`purpose: any`）… 192 は Android のインストール要件、512 はスプラッシュ用
- **`maskable-icon-512x512.png`**（`purpose: maskable`）… 全面をクリーム地で塗り、ロゴは中央 ~64%（セーフゾーン）に収める
- **`apple-touch-icon-180x180.png`**（`index.html` の `<link>`）… **不透明背景必須**（透過だと iOS が角丸にしたとき角が黒くなる）。角丸は焼き込まない
- 元データは `art/icon.svg` / `art/icon-maskable.svg`（`public/` の外＝配信されない）。書き出し方は `art/README.md`。sharp 依存の `@vite-pwa/assets-generator` は使わず canvas でラスタライズする
- **`workbox.globPatterns` に `svg,png` を足さないとアイコンと favicon がオフラインで 404 する**（既定は js/css/html のみ）。追加後の precache 合計は **約 522 KiB**（`maximumFileSizeToCacheInBytes` 既定 2 MB に対して十分・最大ファイルは 453 KiB の JS）

## 横向き前提の扱い
ランドスケープは**技術的に強制できない**（iOS Safari 等で `screen.orientation.lock` が使えない）。取れる手は次の2つだけ:
- PWA manifest で `orientation: landscape` を宣言する（保証ではない・ブラウザのヒント）
- 縦向きを検知して「よこむきに してね」オーバーレイを出す（`isPortrait(width, height)`・`RotateOverlay`）

### ヘッダーは縮ませない・低い画面では絵文字だけにする
横向きスマホでは**ヘッダーの高さが盤面を殺す**。812×375 の実測で、ボタンが幅65〜75pxまで潰されてラベルが縦に折り返し、1つ220pxの高さになっていた（ヘッダー244px＝画面の65%・五線譜は116px）。

- **ボタンは `shrink-0`**（潰れると文字が縦に折り返して高くなる）
- **入りきらなければ `flex-wrap` で行を折る**（はみ出して切れるより良い）
- **高さ500px未満ではラベルを絵文字だけにする**（`isShortScreen()`）。対象年齢は文字を読まないので失うものが少なく、`aria-label` に語を残せば読み上げも保てる

結果（812×375 実測）: ヘッダー 244px → **60px**、盤面 116px → **315px**、倍率 0.232 → **0.631**。音符の列間隔も 25 → **42 CSS px** になった。

レイアウトは 2.2:1 の SVG ビューボックス（1100×500）に固定し、`meet` の左右余白は背景色で吸収する。座標を全部このビューボックス内の定数（`layout.ts`）に置くことで、端末幅ごとの調整を不要にしている。

## 保存
localStorage `doremi.songs.v1` に `SavedSong[]`（ページごとの音名配列）。**外部送信なし・端末内のみ**。

- 上限12曲。超えたら古いものから落とす。純クライアントの軽量保存なので容量管理を持ち込まない
- **パースだけでなく I/O も含めて例外を出さない**。`localStorage.getItem` 自体が投げる環境（Safari でサイトデータを全遮断・一部のプライベートブラウズ構成）があるので `loadSongs` を try/catch で包む。守るのは JSON パースだけでは足りない
- **保存に失敗しても黙って諦める**。quota 超過や書き込み不可でも `saveSong` は例外を投げず、更新後の一覧をそのまま返す（そのセッション中は本棚に反映される＝子どもの前で無反応にはしない）。永続化できなかったことは伝えない——読める年齢ではないうえ、「保存できなかった」と出しても子どもには打つ手がない
- 旧形式（`notes: string[]`）は1ページ曲として読む後方互換を `normalize()` に持つ。`clef` を持たない旧データはト音として読む

## 品質ゲート
CI（`.github/workflows/ci.yml`）は `lint` → `typecheck` → `test`（カバレッジ付き）→ `build` の4段。ローカルも同じ順で回す。

- **lint**: `oxlint --deny-warnings`。warning も EXIT=1 にする（`--deny-warnings` が無いと `react/rules-of-hooks` 以外は実質ノーゲートで、effect の依存漏れ等が素通りしていた）。`.oxlintrc.json` に足したルールは実際に発火するか壊したファイルで確認する — oxlint は存在しないルール名を黙認する。
- **typecheck**: `tsc -b --noEmit`。`build` の第1段とは別に独立ゲートとして走らせる。`tsconfig.app.json` は `strict: true`・`include: ["src"]` なのでテストファイルも型検査対象。`noUncheckedIndexedAccess` は既存コードに約28件出るため別issue（配列アクセスの `undefined` 経路＝白画面クラッシュの本丸）で段階導入する。
- **test**: `vitest run`（`--passWithNoTests` は付けない。テストが消えたら CI を落とす）。カバレッジ閾値は `src/lib/**` に限定（lines 90%）。UI層（`src/components`・`src/App.tsx`）と `src/audio` はテストが揃った時点で対象へ加える。
  - **期待値に実装の定数をそのまま使わない**。`expect(VIEW_H_KEYS).toBe(VIEW_H + KEYBOARD_H)` は `layout.ts` の定義の写しなので、定数をどう壊しても永久に緑になる（ミューテーションで実測: kill率 59%・[#69](https://github.com/mamamakura225/doremi/issues/69)）。体験を決める値（帯の位置・列間隔の下限・鍵盤の表示条件）はリテラルと要件式で固定し、各アサーションに「どの変異で落ちるか」を対応させる。
- `src/components/*.test.tsx` は jsdom に無い SVG 座標変換（`getScreenCTM` / `setPointerCapture`）をスタブで差し込む。`getScreenCTM` には**恒等行列**を返させて client 座標 = viewBox 座標にする。これらのテストが検証しているのは state 遷移とハンドラの分岐で、座標→音高の変換そのものは `pitch.ts` / `layout.ts` / `svgPoint.ts` の純ロジックテストの担当。

### テストのシーム（jsdom で書けるようにする最小の切り出し）
UI 層のバグを純ロジックのテストで捕まえるため、変換を lib の純関数に出す（[#70](https://github.com/mamamakura225/doremi/issues/70)）:

- **`svgPoint.ts`**: `clientToSvg` を `applyMatrix(m, x, y)`（`SVGPoint.matrixTransform` と同じ式）と `clientToSvgPoint(svg, cx, cy)` に分ける。jsdom は `createSVGPoint` を持たず `matrixTransform` を検査できないので、行列の式だけを純関数にして `svgPoint.test.ts` で剪断成分まで固定する。
- **`preview.ts`**: 本棚プレビューの色決定を `previewCells(pages, clef)` に出す。clef を渡し忘れると全灰色になる回帰（[#54](https://github.com/mamamakura225/doremi/issues/54)）を `preview.test.ts` が数値で止める。

実ビューポート・`preserveAspectRatio` の実測・`setPointerCapture` の実挙動が要る3経路（RotateOverlay の向き連動／横スマホのヘッダー絵文字化＋鍵盤非表示／pointerdown→move→up の配置）は jsdom では原理的に検証できないため Playwright（別issue）に回す。
- Node は `.nvmrc`（22）で固定し、CI（`node-version-file`）と Vercel のビルド設定を揃える。

CI を無料枠で回すためリポジトリは public にしている（他リポは private のまま。個人 Actions の無料枠が尽きて CI が起動できなくなった際の対処）。公開前提なので、秘密情報・個人情報をコードにもテストにも置かない。

## デプロイ
Vercel。`main` へのマージで本番反映。

**コミットの著者メールは GitHub アカウントに登録済みのものを使う**（現行 `makura225@gmail.com`）。Vercel は著者メールから GitHub ユーザーを引いて権限を判定するため、**未登録のメールだとビルドが成功しても Vercel チェックだけ FAILURE** になる。no-reply（`284483932+…@users.noreply.github.com`）でも登録済みメールでもよく、要は GitHub 側で当人に紐づくこと。squash マージは GitHub 側の登録メールで著者を書き換えるので、`main` の履歴を見ても取り違えに気づけない（過去に別PCで未登録メールを設定して踏んだ）。
