# どれみ — アートディレクション

絵の約束事を1枚にまとめる。背景・音符・アイコン・マスコット・演出の各issue（親 [#113](https://github.com/mamamakura225/doremi/issues/113)）は、ここに従って作る。何を作るかは [requirements.md](./requirements.md)、実装上の理由は [architecture.md](./architecture.md)。

見本: [`art/moodboard.svg`](../art/moodboard.svg)（画面全体の雰囲気）・[`art/mascot.svg`](../art/mascot.svg)（マスコットの表情4種）。dev サーバで `/art/moodboard.svg` を開くと見られる。

## 目標
**5歳の女の子が「さわりたい」と思う、やわらかくて上質な画面**。ただし、このアプリの学習価値は「音の高さ＝五線の位置」なので、**五線と符頭の位置が読めることを絵より優先する**（ピアノ講師ペルソナの条件）。

## 世界観: 「おんぷのもり」
森のひらけた原っぱで開く、小さな音楽会。

- **五線譜は、原っぱに広げた紙（ステージ）**。背景の絵は紙の外側にだけ置き、紙の上は静かにする
- 空（上）・紙（中央）・丘と花（下）の3層。お道具箱は木のかご
- 花はドレミの7色で咲かせる。色＝音の対応を、画面の飾りでもくり返す

| 候補 | 判断 |
|---|---|
| **おんぷのもり（採用）** | 空と丘で上下の余白を自然に埋められ、五線の紙を「舞台」にしやすい。明るい昼の色で、ドレミの7色とぶつからない |
| おかしのくに | 可愛いが、背景の模様（クリーム・トッピング）が細かくなりやすく、五線の周りがうるさくなる。音符が食べ物に見えて「位置」より「絵」を覚えてしまうおそれ |
| よぞらのほし | 暗い地だと、既存の輪郭色（`#5b524b`）とドレミの暗い色（ド赤・ラ紫）が沈む。パレットを作り直すことになる。季節テーマ（[#111](https://github.com/mamamakura225/doremi/issues/111)）の1つとして後で足す |

## マスコット: ひよこの「ぴぴ」
- まんまるの体・大きめの目・ほっぺ・**シの桃色のリボン**。対象の女の子が「自分の子」と思える要素としてリボンを付けた
- 表情は4種で足りるようにする: **ふつう／にっこり／びっくり／ばんざい**。新しい演出で表情が足りないときは、まずこの4種の組み合わせと動きで表現する
- 1体は 200×200 の座標で描く。塗り: 体 `#ffe38f`（放射グラデーションで上を明るく）・羽 `#ffd166`・くちばしと足 `#ffa94d`・ほっぺ `#ff8fab`（不透明度 0.6）
- 出番: お祝い（[#103](https://github.com/mamamakura225/doremi/issues/103)）・再生中の案内（[#104](https://github.com/mamamakura225/doremi/issues/104)）・空の本棚（[#109](https://github.com/mamamakura225/doremi/issues/109)）・タイトル（[#112](https://github.com/mamamakura225/doremi/issues/112)）。**五線の紙の上には常駐させない**（位置の読みの邪魔になる）。再生中だけ紙の上を渡り歩く
- ことり🐤／くま🐻（音部記号の切替ボタン）は、アイコン（[#101](https://github.com/mamamakura225/doremi/issues/101)）で同じ線・塗りの規則に揃える。くまは2体目のマスコットにしない（描く量が倍になる割に、ヘ音で遊ぶ時間は短い）

## パレット
**正はドレミ7色（`src/lib/colors.ts` の `SOLFA_COLOR`）**。ほかの色はこれを邪魔しない側に置く。

| 役割 | 色 | 備考 |
|---|---|---|
| 輪郭・五線 | `#5b524b`（`OUTLINE_COLOR`） | すべての線画はこの1色。黒は使わない |
| 目 | `#3d3530` | 輪郭よりわずかに濃く、表情を締める |
| 紙（ステージ） | `#fffdf5`（不透明度 0.94） | 五線の地。現行の盤面色 `#fdf6e3` より明るくして、背景と分ける |
| 空 | `#cdeeff` → `#eaf8ff` → `#fdf6e3` | 上から下へ。下端は盤面色に溶かす |
| 丘 | 遠 `#d6efc8`／近 `#bfe3a8` | 低彩度の緑。ファの緑 `#22c55e` と競らない |
| 木（かご・本棚） | 地 `#f3d9ae`／木目 `#e0bd85` | |
| 文字 | `#6b6375` | 現行どおり |

- ステージの外なら、背景の飾りにドレミ7色を使ってよい（花など）。**ステージの上に音符以外の7色を置かない**（音符と見分けがつかなくなる）

## 線と塗り
- **線**: 輪郭色 1色・端と角は丸（`stroke-linecap/linejoin="round"`）。太さは 200 単位あたり 4〜5（マスコット）、盤面では符頭 2〜2.5・符幹 4・五線 3
- **塗り**: ベタ塗り＋**上からのやわらかいハイライト1つ**＋下へのわずかな沈み。放射グラデーションは中心を左上（`cx≈0.35, cy≈0.3`）に置く
- **影**: 落ち影は輪郭色系の半透明（不透明度 0.12〜0.18）・ぼかしのみ。黒い硬い影は使わない
- 細かい模様・テクスチャ・写真調は使わない（縮小時に濁り、容量も増える）

## 可読性の禁則
学習の手がかりが絵に負けないための約束。**数値のあるものはテストで固定する**。

1. **ステージの上には、五線・音部記号・ドレミラベル・足場ガイド・音符・再生中のマスコットだけ**を置く。背景の絵はステージの外
2. 五線・輪郭の地とのコントラストは **7:1 以上**（`contrast.test.ts` の現行基準。ステージ色 `#fffdf5` で 7.49:1、空の上に 0.94 で重ねた最悪値でも 7.41:1）。背景テーマ（[#111](https://github.com/mamamakura225/doremi/issues/111)）を足すときも、全テーマ×7色で同じ基準を通す
3. 符頭の形（傾いた楕円・寸法 `NOTE_HEAD_RX/RY`）と当たり判定は、見た目を変えても動かさない
4. 符頭に顔（目）を描くかは未決（オーナー決定 2026-09-28）。描くなら位置の読みを邪魔しない大きさで、[#100](https://github.com/mamamakura225/doremi/issues/100) で「あり／なし」の見本を並べて決める
5. **動きはすべて `prefers-reduced-motion` で止める**（[architecture.md](./architecture.md) の「動きは prefers-reduced-motion で必ず止める」・`src/motion.test.ts` が検査）

## アセット方式と容量予算
**絵はすべてインライン SVG（React コンポーネント）で描く。ラスター画像は使わない**。

| 理由 | |
|---|---|
| 解像度 | スマホの高 DPR でもにじまない。ビューポート別に複数サイズを用意しなくてよい |
| 容量 | 実測: マスコット4表情で gzip 1.4KB、ムードボード1枚ぶん（空・雲・丘・花・ステージ・音符・かご・マスコット）でも 2.3KB。現行 JS は gzip 126KB（大半が Tone.js） |
| オフライン | JS に入るので、SW のプリキャッシュに自動で乗る。取りこぼしが起きない |
| 色の一貫性 | パレットをコードの定数から引ける（背景テーマの切替も色の差し替えで済む） |

- 予算（gzip）: **アート全体で +25KB まで**。目安は 背景 6KB・マスコット 3KB・アイコン1つ 0.8KB
- 不採用: 生成画像の WebP を背景に貼る案。絵のタッチは豊かになるが、ビューポート別に2サイズ以上が要り（1枚 50KB 前後）、パレットとの一貫性をコードで保てず、画像生成を担う Antigravity が現在 offline で素材を安定して得られない
- 写真やイラスト調の質感がどうしても要る箇所が出たら、その issue で理由と容量を書いてから例外にする

## 動き
- 基本は**ふわっ・ぷにっ**（ease-out、200〜500ms）。弾む・潰れて戻るなど、手触りを感じる動き
- 常時動くもの（雲・案内の揺れ）はゆっくり、同時に2つまで
- お祝い（[#103](https://github.com/mamamakura225/doremi/issues/103)）は段階をつけ、長さは2秒以内。演出中も次の操作をふさぎすぎない

## 制作フロー
- 絵は Claude が SVG で描き、dev サーバで実寸（スマホ横 844×390・タブレット横 1024×768）のスクリーンショットを見て直す。PR には必ず両方のスクショを付ける
- Antigravity に画像を頼む場合（復帰後）は `/bridge-chat` で方向性を合意してから。納品は単体を目視確認し、`git status` でスコープ外ファイルの混入を確かめる。**GitHub への書き込みは Claude だけ**
